# 自绘窗口模型

## 0. 前提

- `cloudui` 管理窗口时，所有自绘窗口都跑在对应的**UI 线程**上；窗口使用分层、置顶的弹出窗。
- 本文只规定窗口之间的关系、职责和绘制方式，不规定宿主往窗口里放什么内容。
- 宿主应用负责进程生命周期、业务数据和事件处理；`cloudui` 负责窗口、布局、绘制、命中与焦点。

## 1. 两类窗口

按「谁管生命周期」分：

| 类 | 说明 | 例子 |
|---|---|---|
| **独立窗口**（independent window） | 有自己那块窗，也有自己的生命周期（UI 线程建、按需显示 / 隐藏、随进程销毁） | 主面板、工具条、提示条 |
| **辅助窗口**（auxiliary window） | 挂在某块独立窗口上的辅助信息 / 提示窗口；它是那块独立窗口的**资产**（asset），生命周期始终绑定到宿主 | 挂在主面板旁边的参考面板、检查器、浮动提示 |

- 每个辅助窗口**有且只有一个所有者**（owner）—— 它的宿主独立窗口。
- 资产挂在宿主名下的**资产表**里：宿主先建好自己那块窗，再建资产；宿主销毁之前先把资产放掉。
  资产的寿命就是这段区间。
- 辅助窗口有「内置种类」：普通辅助窗口与**对话框**（`dialog`）。对话框的正文由库生成，
  创建即模态，详见 [`dialog.md`](dialog.md)。

## 2. 所有权

- 辅助窗口的所有权在它的生命周期内**不发生转移**，也**不会被直接借用**。
  资产表只有「收进来」与「放掉」，没有「取出来」的口子。
- 这条只管辅助窗口。独立窗口之间不受它约束：它们各有自己的生命周期，需要通讯就直接通讯。

## 3. 桥接（bridging）

辅助窗口**不能**直接跟其他辅助窗口通讯，也**不能**跟不是它所有者的独立窗口通讯。
要几何、要开关、要内容，都得**委托它的所有者**。这条委托路叫**桥接**（bridging）。

- 桥由**所有者**这一侧实现（实现上是一个 trait），每次驱动资产时把 `&dyn Bridge` 借给它用一下。
- **借完就还**：借出去的是引用，资产存不下它；想留存就得给自己加生命周期参数，一眼看得出违规。
- 宿主与资产之间只有这条桥：宿主驱动资产（`sync` / `hide` / `set_content`），
  资产经桥向宿主要东西（`host()` / `asset_on()`）。
- 进程级的共用件（共享渲染器、显示器查询那套）不是窗口，不算通讯对象。

## 4. 焦点（focus）

**焦点**是「让窗口具备响应键盘 / 鼠标的功能」的那个特性。规则：

1. **一组里任何时刻恰好一个**：焦点属于一组（一个独立窗口 + 它名下的资产），
   这一组里同一时间只有一个窗口具备焦点 —— 要么是所有者自己，要么是名下的某一件资产。
2. **缺省在所有者身上**：独立窗口创建并显示后总是具备焦点；辅助窗口默认不具备焦点（不响应鼠标 / 键盘）。
   所有者可以把它指定给某件资产，也可以收回来。
3. **允许获取焦点**（`able_to_get_focus`，创建时声明）：辅助窗口想让焦点能落到自己身上，
   得在建它的时候声明；没声明的永远接不住。声明了也只是「能」——创建之后的焦点仍在所有者手上。
4. **指定资产获取焦点**（`designated_asset_to_get_focus`）：独立窗口都具备这个特性 ——
   它能把焦点从自己身上指定给名下某件声明过的资产（按资产的名字认）。只有所有者能指定，资产自己说了不算。
5. **同一所有者的两件辅助窗口之间转移焦点经桥接**：资产之间不直接通讯，
   所以 A1 要让位给 A2 只能委托所有者，路径是 `A1 → 桥 → A（所有者）→ A2`。
6. **指定的后果**：焦点**转移**（不是复制）到那件资产上 —— 此后由它响应鼠标 / 键盘，原先的所有者不再接受。
7. **归还给所有者**（`return_focus_to_owner`）有三条路：所有者主动收回、那件资产收起、它走到生命周期末。
   后两条自动触发（收起时先归还再收起，销毁时先归还再放掉）：焦点不会落在一件看不见、或者马上就要
   没了的窗口上。
8. **克隆 / 窃取来的资产不抢焦点**：通过资产克隆或资产窃取拿到的辅助窗口与原件具备同样的特性，
   但即便它能获得焦点，克隆 / 窃取之后也不会第一时间获得 —— 焦点仍在其所有者、或同一所有者的
   姊妹辅助窗口之一身上；要它拿焦点，还是得所有者指定。窃取时原件被销毁，它原来那一组按规则 7
   自动归还焦点；克隆则两边都不动。

**术语**：把自己的焦点转移给另一个窗口的过程叫**失焦**（unfocusing），获得焦点的过程叫**聚焦**
（focusing）。两边都收得着这两个通知 —— 资产是 `Asset::focusing` / `Asset::unfocusing`，
所有者是 `DesignatedAssetToGetFocus::focusing` / `unfocusing`。

这是**逻辑焦点**，不是操作系统窗口焦点：`cloudui` 的窗口不激活、不抢系统焦点。
落地上「具备焦点」= 这一组里由谁接受输入：没有焦点的一方鼠标一律穿透（点不着），键也轮不到它。

```rust
/// 焦点在谁身上：所有者自己，还是名下的第几件资产。
pub enum Focus {
    Owner,
    Asset(usize),
}

/// 资产：创建时声明「允许获取焦点」（缺省 `false`），并收聚焦 / 失焦通知。
pub trait Asset {
    fn name(&self) -> &str;
    fn able_to_get_focus(&self) -> bool {
        false
    }
    fn focusing(&self) {}
    fn unfocusing(&self) {}
}

/// 桥：资产委托所有者办事的那条路 —— 同一所有者的两件资产之间转手也走这儿。
pub trait Bridge {
    fn designate_focus(&self, name: &str) -> bool;
    fn return_focus_to_owner(&self);
}

/// 独立窗口实现它：把焦点指定给名下某件资产，或者收回来。
pub trait DesignatedAssetToGetFocus {
    fn designate_focus(&self, name: &str) -> bool;
    fn return_focus_to_owner(&self) -> bool;
    fn focus(&self) -> Focus;
    fn focusing(&self) {}
    fn unfocusing(&self) {}
}
```

## 5. 资产克隆与资产窃取

### 5.1 资产克隆（asset cloning）

独立窗口 **A** 想拿到另一个独立窗口 **B** 的资产 **B1**，要同时满足三条：

1. **B1 在生命周期之内**（B 还没把它放掉）；
2. **B1 具备允许克隆的特性** —— 它除了实现 `Asset`，还要额外实现 `Clonable`；
3. **B 收到来自 A 的克隆请求**（独立窗口之间可以直接通讯，请求走它们自己那条路）。

三条都满足时：

- **A 添加一件 A1**：除所有者以外，其余内容与 B1 一样；
- **A1 的所有者是 A**（不复制所有者，也不会是 B）；
- **B1 不受影响**：还归 B，还在 B 的生命周期里 —— 焦点也不受影响；
- **焦点不跟着走**（§4 规则 8）：A1 进来时 A 那一组的焦点不动，还在 A 自己、或它的某件姊妹资产身上。
  A1 能不能获得焦点照旧，但要拿到还是得 A 指定。

```rust
/// 允许被别的独立窗口克隆的资产额外实现它。
pub trait Clonable: Asset {
    /// 克隆一份「除所有者以外」都一样的自己；克隆件由请求方持有、所有者是请求方。
    fn clone_asset(&self) -> Box<dyn Asset>;
}
```

### 5.2 资产窃取（asset stealing）

**A 从 B 克隆 B1 成 A1，且 B1 在克隆之后被立即销毁** —— 这整个过程叫**资产窃取**。

- 之后 A 名下的资产是 A1，不再是 B1；B1 已经被抹去；
- 克隆件是新的资产（不是引用、也不是句柄），所以 B1 被销毁不影响 A1，反过来也一样；
- **焦点两边都不跟着走**：A 那一组按 §4 规则 8 不动；B 那边在 B1 被抹去之前按 §4 规则 7
  自动归还焦点 —— 焦点不会跟着一件正在消失的资产走。

## 6. 渲染

窗口内容只有这一种画法：**先画进一块内存区域，画完整块贴到窗口上**。

- 渲染器把一整帧（阴影、圆角、文字、图标）出成一块**预乘 RGBA 位图**；
- 壳把位图转换成窗口后端需要的格式，一次贴上；没有 `WM_PAINT` 那种「系统擦掉再重画」的时机；
- 一块内存区域 = 一帧：内容变了才重新出图再贴；没变就不贴。贴上去的那一帧一直留在窗口上；
- 要「擦掉」只有两条路：贴一帧新的（覆盖），或者销毁窗口。

**能画的元素**：

| 元素 | 是什么 |
|---|---|
| `text` | 文本 |
| `svg` | SVG 图形，可按 alpha 染色 |
| `img` | 图像，按目标矩形缩放 |
| `line` | 线条 |
| `rect` | 矩形，含圆角矩形与圆形 |
| `path` | 路径（直线 / 贝塞尔 / 闭合） |

窗口里只准经这些元素画，别在别处再抄一遍原语。

### 6.1 区域（region）

窗口内容里的一块**可交互范围**：名字 + 命中形状（矩形 / 圆角 / 圆 / 线段 / 路径）+ 能不能拖。

- 元素只管画；鼠标点击 / 拖拽看区域；
- 命中规则：后写的区域盖住先写的；先看区域，再看元素；
- 区域可以带并集 / 差集形状；命中检测只做成员判断，不做轮廓布尔运算；
- 区域形状不限于矩形，支持内含 / 相交 / 重合 / 相离的关系查询。

## 7. 实现落点

- **独立窗口模板**（`cloudui::window::IndependentWindow`）：注册窗口类，建分层、置顶、不抢焦点的弹出窗，
  并管名下的资产。`Drop` 里先放掉资产，再销毁自己那块窗。焦点也由它兜着：实现
  `DesignatedAssetToGetFocus`，指定 / 收回时自己失焦 / 聚焦，并给窗口过程一个 `focused()`；
  焦点不在自己身上时整块让开，鼠标穿透。
- **辅助窗口模板**（`cloudui::window::AuxiliaryWindow`）：资产用的那块分层面板。外观（背景、圆角、阴影）
  走主题；尺寸与跟宿主的间隙是可设的属性，没设过时按宿主的形状算默认；`show(宿主内容区矩形, 排布方向)`
  贴宿主摆位 —— 竖排贴右边、放不下换左边；横排贴下边、放不下换上边；最后夹进所在显示器的工作区。
- **资产层**（`cloudui::asset`）：`Asset`、`Assets`（宿主名下的资产表 + 这一组的焦点）、
  `Bridge`、`Host`（宿主喂给资产的形状：内容区矩形 / 排布方向 / 附加状态）、
  `Focus`、`DesignatedAssetToGetFocus`。
- **内容层**（`cloudui::document`）：一份声明式 `Document`，包含页面树、绘制元素、命中区域和文本宿主。
  窗口通过 `set_document` 换内容，通过 `set_events` 收鼠标 / 键盘事件。
- **布局**（`cloudui::layout`）：把页面树排成绝对几何，产出一份新的 `Document`。
- **绘制**（`cloudui::render`）：`Renderer::render_document` 把 `Document` 出成位图和命中区域。
- **主题**（`cloudui::theme`）：颜色、字体、圆角、阴影等绘制参数；见 [`theme.md`](theme.md)。

宿主不直接操作窗口句柄；它只创建窗口、给 `Document`、收事件。窗口后端（Windows 分层窗口等）属于
`cloudui` 内部实现，换后端不影响上层契约。

## 8. 内置对话框（dialog）

对话框是辅助窗口的一种**内置种类**（`AssetKind::Dialog`），正文布局由库生成，调用方不写 JSON。
具体界面、属性、拖拽与输入屏蔽见 [`dialog.md`](dialog.md)；这里只定它在窗口模型里的位置：

- **创建即模态**：`Assets::add` 自动把它压到模态栈顶；栈顶原有普通模态或外层 dialog 先临时挂起，
  dialog 销毁后再恢复。同一所有者可以嵌套 dialog。
- **生命周期内不可取消**：`set_modal(false)` 与 `hide` 都非法；只能 `close`。
- **位于最顶层**：dialog 是所有者的 owned window，建出来就置顶；每次显示 / 开蒙版后再抬到最前。
- **焦点**：创建时如果焦点在别的资产上，先经桥接交还所有者，再由所有者指定给 dialog。
- **可选蒙版**：dialog 可以要求所有者开蒙版，销毁前恢复原蒙版。
- **拖拽**：拖动 dialog 时所有者按相同位移移动，但保持输入屏蔽；编辑框宿主与蒙版是独立顶层窗口，
  由 dialog 按相同位移一起搬。
- **输入屏蔽**：所有者名下的 RichEdit 宿主是独立顶层窗口，`EnableWindow(owner, FALSE)` 管不到，
  dialog 打开期间必须逐个屏蔽并在关闭时恢复（见 [`text-edit.md`](text-edit.md)）。
